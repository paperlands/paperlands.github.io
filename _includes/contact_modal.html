{%- comment -%} The letter to PaperLand — the site's one way of writing to us, on every page. FOUR FILES ARE THE WHOLE COMPONENT, and this is one of them: this include the markup: a native assets/css/components/contact.css the skin, in the shared app.css entry assets/js/contact.js the behaviour, which opens it and owns the status line _data/contact.yml the words, the route, the arrival Placement is the only thing a page does: _layouts/default.html, _layouts/folio.html and _layouts/note.html — the three that carry the nav — each include this once. ONE LETTER PER PAGE: the id is the component's, so a page must not place a second one. THE ROUTE IS NOT WRITTEN HERE OR IN THE SCRIPT. `_data/contact.yml` declares `route` and `arrival`; this include writes them onto the dialog as data-contact-route and data-contact-arrival, and the script reads them back. So the nav's "Join Us", a link in a note's prose, _pages/contact.md (which IS the route) and the cold arrival all resolve through one pair of values — a moved route or a second surface is a data edit, not a hunt. The consequence to keep: any link to `route` opens the letter WHERE THE READER IS, and the href is left alone, so a modifier-click, a middle-click or no JavaScript still resolves the route — which then redirects to `arrival`, where the script opens the dialog. That is the whole difference between a reader related to a page and a cold arrival. A native , so the browser owns the hard parts: the focus trap, Escape, the modal stack, and inertness of everything behind it. `showModal()` puts the panel in the top layer, above the fixed nav and the grain, with no z-index to maintain. The form is `_includes/contact_form.html` in its `night` skin, which is the modal's own, under `id_prefix="contact-"`: /lesson-plans carries the paper form, so the two must not share field ids. Turnstile is NOT emitted with the form — `lazy_turnstile: true` leaves the script to open it the first time the dialog does, so a reader who never opens the letter never pays for the challenge. `return_url` defaults to the page the reader wrote from, so a note gets its own reader back. Bound by components/contact.css, which is in the shared entry: the classes are `contact*` because the letter belongs to no look — the look's own probe (design/probe/looks.py) requires every class a [data-look] rule names to be namespaced to that look, and this panel is opened from all of them. Params: none. The words are _data/contact.yml. THE WORDS ARE MARKED UP, BECAUSE THE SITE'S WORDS ARE. Each prose field is read with `| markup` (_plugins/site_markup.rb): a `[[note|label]]` resolves to that note's address, and the string is read as kramdown, so the letter links and wears faces exactly as a note's prose does. This include says only WHICH fields are prose — title, title_em, lede, address, and the receipt's two messages below. `message_placeholder` is an attribute, so it is not, and takes no markup. {%- endcomment -%} {%- assign letter = site.data.contact -%}

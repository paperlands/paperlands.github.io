{%- comment -%} The standing navigation. Reads _data/nav.yml — one source for every link, so the desktop bar, the mobile panel and the Helios folio nav cannot drift. Params: tone "light" | "dark" — the surface the nav SITS ON, not the ink colour. Defaults to site.data.nav.default_tone. light = over a light background -> dark ink dark = over a dark/photographic background -> light ink Call sites pass nothing and get the light tone. Pages that sit over a dark hero set `nav_tone: dark` in front matter (see _layouts/default.html). The markup is deliberately data-attribute driven, not id driven: the previous version queried #mobile-menu, #mobile-menu-overlay and #mobile-menu-close by global id from an inline script, which meant a second nav on a page would collide. Behaviour lives in assets/js/nav.js and scopes to this root. {%- endcomment -%} {%- assign nav = site.data.nav -%} {%- assign tone = include.tone | default: page.nav_tone | default: nav.default_tone | default: 'light' -%}
